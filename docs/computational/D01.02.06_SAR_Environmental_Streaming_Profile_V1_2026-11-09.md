# SAR Environmental Streaming Profile

Document ID: D01.02.06 

Document Class: Modality Contract Profile

Project: Self-Aware-Room (SAR)

Status: Version 1 draft

Date: 2026-11-09

Author: Jabber Bin Kibria

Supervisor: Professor David B. Smith

## 1. Purpose

This document defines the environmental sensing modality profile layered on the SAR Shared Streaming Contract (D01.02).

It specifies the environmental-required fields and their data types, the event model, retention behavior, and conformance checks for environmental producers. The reference producer for Version 1 is the SAR Environmental Node: an ESP32-WROOM-32 reading a Bosch BME680 (temperature, relative humidity, barometric pressure, gas resistance) over I2C.

## 2. Contract Position

- This profile applies when `modality` is `environmental`.
- Base contract: D01.02 Shared Streaming Contract.
- Environmental profile: this document.
- This profile is an event-based contract. The audio profile (D01.02.01) is the exemplar of a clocked, frequency-based contract; this profile is derived from the same base contract for a source that reports events.
- This profile extends the base contract by composition. It adds fields and semantics and does not change any base rule.

### 2.1 How This Profile Relates to the Base Contract and the Audio Exemplar

The base contract defines five required fields and three optional ones. The audio profile adds the fields a continuous sample stream needs. This profile adds the equivalent fields for an event-based sensor.

| Concern | Base contract (D01.02) | Audio profile (D01.02.01) | Environmental profile (this document) |
|---|---|---|---|
| Source kind | Clocked or event-driven | Clocked stream | Event-driven |
| What a frame is | Smallest ordered transport unit | A short window of audio samples | One event, with the full reading set taken at that moment |
| Identity and order | `source_node_id`, `source_id`, `modality`, `frame_index` | Same | Same |
| Timing | `source_capture_time`, `source_latency_ms` (optional) | Same; rate given by `sample_rate_hz` | Same; `sample_interval_ms` and `heartbeat_interval_ms` instead of a sample rate |
| What produced the data | Not defined | `encoding`, `sample_format` or `bit_depth`, `channel_count` | `sensor_model`, `sensor_config` |
| Why this frame was sent | Not defined | Every frame in sequence; optional gating (`gate_state`) | `event_type`: `startup`, `change`, or `heartbeat` |
| Suppression rule | Not defined | Gate thresholds in dBFS, pre-roll and post-roll | Change thresholds per quantity (`threshold_*`) |
| Payload | In-frame values or a reference | Sample chunk, or a reference to stored audio | Named measurement values, always in-frame |

## 3. Normative Terms

MUST, SHOULD, and MAY are normative.

## 4. Environmental Required Fields

### 4.0 Environmental Frame Definition

- An environmental frame is a discrete event payload: one event from the node, carrying one complete reading set (every quantity the sensor measures, captured in the same measurement cycle).
- An environmental source is event-driven. The node samples its sensor at a fixed interval (`sample_interval_ms`) but emits a frame only when an event occurs (Section 5). Frames therefore arrive at irregular intervals.
- `frame_index` MUST be monotonic within a source stream or session, and MUST count emitted frames, not samples taken.
- A reboot of the producer starts a new session and `frame_index` MAY restart at 0. Producers SHOULD emit `source_session_id` so L1 can tell a restart from a reordering.
- `payload` MUST carry in-frame values. Environmental reading sets are small, so reference descriptors are not used by this profile.

### 4.1 Frame Fields and Data Types

Field placement follows the audio exemplar: fields that describe the source and the frame sit on the frame, and the measured values sit in `payload`.

Base fields (from D01.02, restated with the values this profile fixes):

| Field | Required | Type | Rule |
|---|---|---|---|
| `source_node_id` | yes | string | Identifies the physical node, e.g. `esp32_env_01` |
| `source_id` | yes | string | Identifies the sensor stream on that node, e.g. `bme680_01` |
| `modality` | yes | string | MUST be `environmental` |
| `frame_index` | yes | unsigned integer | Monotonic per session (Section 4.0) |
| `payload` | yes | object | Measurement values (table below) |
| `source_latency_ms` | no | number | Time in ms from the start of the measurement cycle to frame emit |
| `source_capture_time` | no | string, ISO 8601 UTC | Only when the node has a synchronized clock |
| `source_frame_id` | no | string | Source-native frame ID, if the node assigns one |

Required profile fields on the frame:

| Field | Type | Unit | Rule |
|---|---|---|---|
| `sensor_model` | string | none | Sensor part, e.g. `BME680` |
| `event_type` | string | none | `startup`, `change`, or `heartbeat` (Section 5) |
| `sample_interval_ms` | unsigned integer | ms | Interval between measurement cycles; greater than 0 |
| `heartbeat_interval_ms` | unsigned integer | ms | Longest silence before a heartbeat event; greater than 0 |
| `threshold_temperature_c` | number | degrees Celsius | Change threshold; greater than 0 |
| `threshold_relative_humidity_pct` | number | percent RH | Change threshold; greater than 0 |
| `threshold_pressure_hpa` | number | hPa | Change threshold; greater than 0 |
| `threshold_gas_resistance_ohm` | number | ohm | Change threshold; greater than 0 |

Optional profile fields on the frame:

| Field | Type | Unit | Notes |
|---|---|---|---|
| `source_session_id` | string | none | Random value chosen at boot; changes on every restart |
| `source_uptime_ms` | unsigned integer | ms | Node uptime at capture; not a wall-clock time |
| `firmware_version` | string | none | Producer firmware identifier |
| `sensor_config` | object | none | Sensor settings in force (below); SHOULD be sent on `startup` events |

`sensor_config` fields for the BME680: `oversampling_temperature`, `oversampling_humidity`, `oversampling_pressure` (unsigned integer, x), `iir_filter_size` (unsigned integer, coefficient), `gas_heater_temp_c` (unsigned integer, degrees Celsius), `gas_heater_duration_ms` (unsigned integer, ms).

Required `payload` fields. A producer MUST emit every quantity its sensor measures, using these names and units:

| Field | Type | Unit | Notes |
|---|---|---|---|
| `temperature_c` | number | degrees Celsius | Compensated sensor value, no offset applied |
| `relative_humidity_pct` | number | percent RH | |
| `pressure_hpa` | number | hPa | Station pressure, not sea-level corrected |
| `gas_resistance_ohm` | number | ohm | Raw MOX gas resistance; 0 when the reading is not valid |
| `gas_heater_stable` | boolean | none | True when the gas reading was taken with a stable heater |

Rules:

- Field names carry their unit as a suffix. A producer MUST NOT emit a quantity in a different unit under these names.
- Values MUST be raw sensor outputs. Calibration offsets and derived quantities are applied downstream (Section 4.2).
- A `payload` field MUST NOT reuse the name of a frame field. The frame's own value is the single authoritative one.
- A frame MUST NOT carry fields that belong to another modality's profile (for example `encoding` or `sample_rate_hz`).
- A wired node without a synchronized clock MUST omit `source_capture_time` rather than send an unsynchronized time. L1 backfills it under D01.02 Section 5.2.

Example frame (one line of JSON as emitted by the reference producer, wrapped here for reading):

```json

  "source_node_id": "esp32_env_01",
  "source_id": "bme680_01",
  "modality": "environmental",
  "frame_index": 42,
  "source_latency_ms": 187,
  "sensor_model": "BME680",
  "event_type": "change",
  "sample_interval_ms": 2000,
  "heartbeat_interval_ms": 60000,
  "threshold_temperature_c": 0.5,
  "threshold_relative_humidity_pct": 1.0,
  "threshold_pressure_hpa": 0.5,
  "threshold_gas_resistance_ohm": 5000,
  "source_session_id": "9f3a1c07",
  "source_uptime_ms": 913250,
  "firmware_version": "sar_env_node_bme680/1.2.0",
```

### 4.2 Frame Versus Derived Observation Semantics

- A frame is the ingest transport unit for ordering, timing, and payload carriage.
- A derived observation is an analysis unit computed from one or more frames, for example an air-quality index, dew point, sea-level pressure, a rolling average, or an occupancy inference.
- L0/L1 transport conformance applies to frames, not to derived observations.
- A derived observation MUST preserve provenance to its source frame indices or frame IDs.
- Derived values MUST NOT overwrite or replace the raw payload values of a frame.

### 4.3 Frame Object

The frame is implemented as a small pair of Python classes in [`frames.py`](https://github.com/JabberBinKibria/Self-Aware-Room/blob/main/docs/sensors/Src/frames.py). They use only the Python standard library and do not depend on `sar_core`.

| Class | Represents | Holds |
|---|---|---|
| `BaseEdgeFrame` (abstract) | D01.02 base contract | The five required and three optional base fields, and the checks every sensor shares |
| `EnvironmentalEdgeFrame` | This profile | The Section 4.1 profile fields, the `event_type` and threshold checks, and the required measurements in `payload` |

Behavior defined by the base class, so that a class for another sensor gets it by inheriting:

- `modality` is fixed by the class, not supplied per frame.
- A frame with a missing required field, a negative `frame_index`, or an unknown field is rejected when it is built.
- A payload that reuses a frame field name is rejected.
- `to_dict()` returns the frame as a plain record ready to save as JSON.

A profile for another sensor is added by writing one more class that inherits from `BaseEdgeFrame` and declares that sensor's fields.

Note on the existing pipeline code: `EdgeObservationFrame` in `sar_core` requires the audio fields `encoding`, `sample_rate_hz`, and `channel_count` for every frame, so it cannot represent an environmental frame as it stands. Connecting this frame object to the `sar_core` L1 stage is future work and is not part of Version 1.

## 5. Event Model and Change Thresholds

Environmental quantities change slowly, so the node reports events instead of a continuous stream. Thresholds play the role that gating plays in the audio profile.

Event types:

| `event_type` | Emitted when |
|---|---|
| `startup` | First frame of a session |
| `change` | Any quantity differs from its value in the last emitted frame by at least its threshold |
| `heartbeat` | `heartbeat_interval_ms` has passed since the last emitted frame |

Rules:

- The first frame of a session MUST be a `startup` event.
- A `change` event MUST be emitted when any quantity passes its threshold.
- A `heartbeat` event MUST be emitted when the heartbeat interval passes with no other event.
- Every event MUST carry the full reading set, not only the quantity that changed.
- Comparison is against the last emitted frame, not the previous sample, so slow drift still produces a `change` event once it accumulates past the threshold.
- Every frame MUST carry the thresholds and intervals in force, so a consumer can tell what was suppressed between two events.

### 5.1 Heartbeat and Silence Policy

- A quiet room and a dead node look the same without a heartbeat. The heartbeat MUST NOT be disabled.
- L1 SHOULD treat a source as stale when no frame arrives within two heartbeat intervals.

### 5.2 Tentative Default Parameters

These are starting values carried over from Stage B wired baseline validation. They are not final acceptance thresholds and should be re-evaluated against live room data.

| Parameter | Tentative default | Unit | Notes |
|---|---|---|---|
| `sample_interval_ms` | 2000 | ms | Measurement cycle |
| `threshold_temperature_c` | 0.5 | degrees Celsius | |
| `threshold_relative_humidity_pct` | 1.0 | percent RH | |
| `threshold_pressure_hpa` | 0.5 | hPa | |
| `threshold_gas_resistance_ohm` | 5000 | ohm | Absolute threshold; a relative (percent) threshold may suit gas better and is an open question |
| `heartbeat_interval_ms` | 60000 | ms | |
| `default_source_latency_ms` | 0.0 | ms | L1 fallback when L0 gives no latency estimate |

## 6. Retention and Storage Modes

- Environmental frames are small. L1 SHOULD retain every received frame in full, with values in-frame.
- No raw-artifact reference store is required for this modality.
- Version 1 of the reference receiver does not run the `sar_core` L1 stage. It performs the two L1 timing duties locally: it stamps each frame with `receipt_time` when the frame arrives, and adds `estimated_capture_time`, computed as `receipt_time` minus `source_latency_ms`.
- Until a database is selected, the reference receiver appends each timestamped frame to a JSON Lines flat file on the computer the node is connected to (by default `data/env_node_frames.jsonl`, next to the receiver script).

### 6.1 Low-Information Policy

- Samples that did not produce an event are not recoverable. The thresholds and heartbeat interval carried on each frame are the audit trail for that suppression.
- If L1 or a downstream store thins environmental data further, it MUST keep the timing bounds and the policy that was applied.

### 6.2 Data Quality and Warm-Up Policy

- Gas resistance from a MOX sensor is not meaningful until the heater is stable. A frame with `gas_heater_stable` = false MUST still be emitted, and consumers MUST NOT use its `gas_resistance_ohm` value.
- Gas resistance drifts during the first hours to days of operation of a new sensor (burn-in) and for several minutes after each power-up. Consumers SHOULD treat early-session gas values as unsettled. `source_uptime_ms` and `source_session_id` support that decision.
- Gas resistance is a relative signal. It is not a calibrated VOC concentration, and it is not comparable between two sensors without a per-sensor baseline.
- The sensor's heater and the node's own electronics warm the sensor. `temperature_c` typically reads above true room temperature and `relative_humidity_pct` correspondingly low. Producers MUST NOT apply a correction; calibration offsets belong downstream with provenance.

## 7. Conformance Checklist

An environmental L0/L1 path is conformant when:

1. Base D01.02 required fields are present on every frame.
2. Section 4.1 required profile fields are present on the frame and required measurements are present in `payload`, with the stated names, types, and units.
3. `frame_index` is monotonic within a session and counts emitted frames.
4. `startup`, `change`, and `heartbeat` events are emitted as specified in Section 5, each with the full reading set.
5. The ingest side stamps `receipt_time` on arrival and backfills the capture time from `source_latency_ms` when the node has no synchronized clock (D01.02 Section 5.2).
6. Frames with an unstable gas heater are emitted and flagged, not dropped.
7. Payload values are raw sensor outputs, with no node-side calibration or derived quantities substituted.
8. Frames with unknown fields, another modality's fields, or payload keys that reuse frame field names are rejected at ingest.
9. If derived observations are produced, frame provenance is preserved (Section 4.2).

## 8. Reference Implementation

The reference implementation is in `docs/sensors/Src/`. It has been run on the Stage B hardware (ESP32-WROOM-32 with the Adafruit BME680 breakout).

| Component | Role | Language | Path | Link |
|---|---|---|---|---|
| Environmental node firmware | L0 producer; runs on the ESP32 | C++ (Arduino) | `docs/sensors/Src/sar_env_node_bme680.ino` | [sar_env_node_bme680.ino](https://github.com/JabberBinKibria/Self-Aware-Room/blob/main/docs/sensors/Src/sar_env_node_bme680.ino) |
| Frame classes | Defines and checks a frame | Python | `docs/sensors/Src/frames.py` | [frames.py](https://github.com/JabberBinKibria/Self-Aware-Room/blob/main/docs/sensors/Src/frames.py) |
| Environmental node receiver | Receives frames, timestamps and saves them | Python | `docs/sensors/Src/env_node_receiver.py` | [env_node_receiver.py](https://github.com/JabberBinKibria/Self-Aware-Room/blob/main/docs/sensors/Src/env_node_receiver.py) |
| Sample output | Frames recorded from the node on 2026-11-10 | JSON Lines | `docs/sensors/Src/env_node_frames.jsonl` | [env_node_frames.jsonl](https://github.com/JabberBinKibria/Self-Aware-Room/blob/main/docs/sensors/Src/env_node_frames.jsonl) |

Data flow in Version 1:

```
BME680 -> ESP32 firmware -> USB serial (one JSON frame per line) -> env_node_receiver.py -> env_node_frames.jsonl
```

Run the receiver from the folder that holds it (requires `pyserial`; `frames.py` must be in the same folder):

```
python env_node_receiver.py --port COM11
```

Each saved line is the frame as sent, with `receipt_time` and `estimated_capture_time` added in front. Both are in UTC.

Transport status: Version 1 sends frames over USB serial at 115200 baud. A wireless transport is planned. It will carry the same frame and only replace the line source in the receiver.
